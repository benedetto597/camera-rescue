# Selector Múltiple Dinámico & UI Builder (`v1.3.0`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Evolucionar Camera Rescue desde `v1.2.0` hasta `v1.3.0` incorporando un checklist interactivo de sensores funcionales tras el escaneo, generación dinámica de botones/tarjetas de rescate (`DynamicUiBuilder`), accesos directos dinámicos en el Launcher (`RescueShortcutManager`) y Quick Settings Tile (`CameraRescueTileService`).

**Architecture:**
1. **`RescueActionSpec` & `SensorSelectionState`**: Modelos puros inmutables y utilidades de saneamiento/persistencia para representar acciones dinámicas de cámara y la selección del usuario sobre sensores sanos.
2. **`DynamicUiBuilder` & `SensorScanner` fix**: Motor puro que genera tarjetas de rescate y atajos adaptados a los sensores seleccionados (o fallback por perfil antes del escaneo), junto con normalización de polaridad `facing` (`0=BACK, 1=FRONT`) y deduplicación en `SensorScanner`.
3. **Integraciones Android (`RescuePreferences`, `RescueShortcutManager`, `CameraRescueTileService`)**: Persistencia en `SharedPreferences`, registro dinámico de `ShortcutInfo` y mosaico de Ajustes Rápidos compatible con Android 14+ (`PendingIntent` en API 34+).
4. **Integración en `MainActivity`, `FrontCameraController` y Sincronización `v1.3.0`**: Checklist con `CheckBox` en el escáner, reconstrucción dinámica de tarjetas y botones frontales, despacho de intents de atajos con consumo seguro (`singleTask`) y actualización de scripts/CI.

**Tech Stack:** Java 17, Android SDK 34 (`minSdk = 30`, `targetSdk = 34`), APIs estándar del SDK sin dependencias externas, pruebas unitarias puras en Java (`scripts/test-local.ps1`), compilación local `aapt2`/`javac`/`d8`/`zipalign`/`apksigner` (`scripts/build-local.ps1`).

## Review Focus
1. **API 34 `TileService.startActivityAndCollapse`:** On Android 14+ (`Build.VERSION.SDK_INT >= Build.VERSION_CODES.UPSIDE_DOWN_CAKE`), calling `startActivityAndCollapse(Intent)` throws `UnsupportedOperationException` when `targetSdk = 34`. `CameraRescueTileService.onClick()` MUST branch: use `startActivityAndCollapse(PendingIntent)` with `FLAG_UPDATE_CURRENT | FLAG_IMMUTABLE` on API 34+, and `startActivityAndCollapse(Intent)` on API 30–33.
2. **`SensorScanner` facing polarity & deduplication:** Android `CameraCharacteristics.LENS_FACING_FRONT` is `0` and `LENS_FACING_BACK` is `1`, whereas `DiscoveredSensor` uses `0 = BACK, 1 = FRONT`. `SensorScanner.testCameraSensor()` MUST normalize `facing = (facingVal != null && facingVal == CameraCharacteristics.LENS_FACING_FRONT) ? 1 : 0;` and MUST skip adding a profile `standaloneId` if it is already in `publicCameraIds` (e.g., Galaxy S9/Note 9 where `rearMainStandaloneId` is `"0"`).
3. **Zero selected/healthy rear sensors:** `DynamicUiBuilder.buildRearActionSpecs()` must return an empty list (never crash), and `MainActivity` must display an informative empty-state card while keeping front camera controls operational if front lenses are healthy.
4. **`singleTask` Shortcut Intent Consumption:** `MainActivity` must handle custom shortcut actions in both `onCreate` and `onNewIntent`, and immediately reset `setIntent(new Intent(Intent.ACTION_MAIN))` after dispatching so resuming from Recents never re-launches Samsung Camera in a loop.
5. **Single-rear / no-telephoto models (e.g., Galaxy A54, Z Flip, S9):** When `profile.rearTeleStandaloneId == null` or tele sensor is not selected, generated button subtitles and descriptions must NOT claim "3x Tele" support.
